# Адаптация Mlution к ТЗ «Альфа Хак / AutoML»

Основание: предоставленный пользователем PDF «Альфа Хак_AutoML .pdf» (20 страниц).
Интерфейс дополнительно проверен по публичному baseline.py, ссылка на который
встроена в PDF. Эталон сохранён для чтения в `competition/baseline-reference.py.txt`.
Он не исполнялся. Список разрешённых версий — `competition/requirements-organizer.txt`.

## Что изменено

| Требование | Реализация |
| --- | --- |
| ZIP, solution.py в корне, Python 3.12 | Корневая точка входа и `competition/package_solution.py`; переносимый архив без зависимости от веб-приложения |
| `solution.py task.md`, переменные baseline | `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`; относительные материалы рядом с task.md |
| train/test/dictionary/sample | Проверка схемы, определение цели и роли ID, сохранение строковых меток и порядка sample_submission |
| Разные задачи одним кодом | Регрессия и классификация без имён конкретных публичных таргетов в логике |
| AutoResearch | Базовый результат, гипотезы Qwen по профилю и истории, код экспериментов, измерение метрики, принятие/отклонение, следующие итерации |
| Собственная валидация | Одинаковый training-only holdout для всех кандидатов; стратификация классификации; test labels не читаются |
| Готовый файл до дедлайна | Ранний резервный CSV и атомарное обновление после улучшения; лучшие рецепты переобучаются на всём train |
| Ограничения | До 10800 секунд, до 8 потоков, таймауты дочерних процессов, лимиты вызовов и токенов; CPU/RAM контейнера задаёт платформа |
| Qwen организаторов | Отдельный планировщик без чтения прежних LLM_* настроек; другой модельный провайдер отклоняется |
| Разрешённые библиотеки | Минимальная среда с точными версиями из allowlist; дополнительные бустинги обнаруживаются, если установлены платформой |
| Итоговые баллы | Реализованы формулы нормирования RMSE и Macro F1 и среднее двух баллов; реальный public/private score не выдумывается |
| Работа в существующем продукте | `/competition`, защищённый API загрузки/запуска/скачивания, существующие RQ-запуски и отмена, проверка владельца |

## Быстрый локальный запуск

Установите Python 3.12 и минимальный набор разрешённых библиотек:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r competition/requirements-runtime.txt
.\.venv\Scripts\python.exe solution.py C:/path/to/task.md --offline --time-budget 60 --max-experiments 3 --threads 1
```

Для агентного режима задайте выданные организаторами OPENAI_* переменные в
окружении и уберите `--offline`. Не отправляйте ключи в чат и не добавляйте их
в ZIP. Передача ключа через поля веб-формы не требуется.

Сборка архива:

```powershell
python competition/package_solution.py
```

Результат: `output/competition/mlution-solution.zip`. Архив включает только
переносимые модули, точку входа, минимальный requirements, инструкцию и манифест
контрольных сумм. В нём нет .env, пользовательских файлов, моделей или данных.
Загрузка на платформу автоматически не выполняется.

## Веб-интерфейс

```sh
docker compose -f docker-compose.yml -f docker-compose.competition.yml up --build -d
```

Откройте `/competition` после входа. Загрузите четыре CSV и вставьте содержимое
task.md. В локальном режиме оставьте флажок «Локальная проверка без LLM».
Для Qwen-режима настройте OPENAI_* у backend и worker через окружение Compose
и снимите флажок. Лимит отдельного CSV — `COMPETITION_MAX_UPLOAD_MB`, по умолчанию
100 MB. Пользователь может запустить только одну задачу одновременно.

На платформу организаторов отправляется **переносимый ZIP**, а не веб-стек.
PostgreSQL, Redis и frontend в конкурсный архив не включаются.

- Переносимый ZIP: **2 passed**; архив извлекается и его точка входа действительно

  Среда: Python 3.12, NumPy 1.26.4, pandas 2.2.3, scikit-learn 1.5.2.
- Ruff: ошибок нет. Production-сборка Next.js завершилась успешно, включая `/competition`;

- Объединённая конфигурация Compose прошла `docker compose ... config --quiet`.

- Итоговый ZIP содержит 14 файлов, 19998 байт. Проверены SHA-256 каждого исходника

  `473570f538b304026fef6f762ae9dc8a119e60d3313af9c803d3bf18e74ca3ef`.

Backend-тесты покрывают реальные обучения, соответствие сабмита, неизвестные
категории, пустые признаки, строковые классы, резервный результат при ошибках,
ограниченный Qwen-контракт с подменённым HTTP-транспортом, отмену дочернего
процесса, исключение credentials из его окружения, API и изоляцию владельцев.
`competition/tests` извлекает ZIP и запускает именно его `solution.py` на двух
новых синтетических задачах с точными версиями NumPy/pandas/scikit-learn.

```powershell
cd backend
python -m pytest -q
python -m ruff check app tests migrations
cd ..
python -m pytest -q competition/tests -c competition/pytest.ini
cd frontend
npm run lint
npm run typecheck
npm run build
```

Реальный API Qwen без выданных credentials и реальные public/private-датасеты
не проверены. Успешные синтетические тесты подтверждают интерфейс и исполнение,
но не место в лидерборде. Docker-runtime проверяется отдельно от переносимого
Python-запуска. `--offline` не считается LLM-агентом.

LLM выбирает из проверяемых типизированных рецептов моделей, параметров и
предобработки. Произвольный Python из LLM не исполняется; новые операции требуют
добавления доверенных рецептов. Это ограничивает простор генерации, но сохраняет
воспроизводимость и предотвращает выполнение инструкций из текста датасета.
Time-series/grouped validation, несколько целей и форматы вне одной табличной
регрессии/классификации пока не реализованы. Абсолютный выход за каталог задачи
отклоняется; нестандартный интерфейс новых материалов нужно сверить с организаторами.
