# Mlution AutoResearch — конкурсное решение

Точка входа соответствует опубликованному baseline: `python solution.py task.md`.
Python 3.12. PostgreSQL, Redis, веб-сервер и MCP для этого запуска не нужны.

В одном каталоге должны находиться:

```text
task.md
train.csv
test.csv
data_dictionary.csv
sample_submission.csv
```

Для агентного режима передайте в окружении процесса выданные организаторами
`OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`. Поддерживается Qwen3.8-27B;
остальные провайдеры приложения не используются. Не помещайте ключ в архив.
Библиотеки на платформе предоставляет организатор. Для локального окружения
можно установить минимальный набор из `requirements.txt`.

```sh
python solution.py /path/to/task.md
```

Без ключа, только для локальной проверки работоспособности:

```sh
python solution.py /path/to/task.md --offline --time-budget 60 --max-experiments 3 --threads 1
```

`--offline` использует локальные эвристики и не является проверкой LLM-агента.
По умолчанию бюджет — 10800 секунд, до 24 экспериментов и до 8 CPU-потоков.
Сначала сохраняется резервный CSV, затем он заменяется только победившим
валидированным вариантом. Финальная модель переобучается на всех размеченных
строках; число, имена и порядок столбцов сабмита и идентификаторы берутся из
`sample_submission.csv`. Имена строковых классов, включая `01`, сохраняются.

Имя выходного CSV извлекается из обычных упоминаний `submission*.csv` или
`predictions*.csv` в условии; по умолчанию это `submission.csv` рядом с `task.md`.
Можно явно задать `--output predictions.csv`. Выход должен находиться внутри
каталога задачи и не заменять входные файлы.

`research.json` содержит профиль, планы, измеренные метрики, принятие/отклонение
гипотез, затраты времени и счётчики LLM. В `.mlution/<run-id>/` сохраняются
сгенерированные скрипты экспериментов и их локальные журналы. `MANIFEST.json`
в архиве фиксирует SHA-256 исходников.

Рецепты моделей: линейная модель, HistGradientBoosting, ExtraTrees, RandomForest;
CatBoost, LightGBM и XGBoost доступны при наличии этих разрешённых библиотек в
среде платформы. Ни предобученные веса, ни внешние датасеты не загружаются.
LLM предлагает типизированный план; Python-код строится из доверенного шаблона,
а не исполняется произвольно из ответа модели.

Поддерживается табличная регрессия и классификация с одной целевой колонкой.
Основные конкурсные метрики — RMSE и Macro F1; также распознаются MAE, R²,
Accuracy и бинарная ROC AUC. Для остальных форматов требуется расширение
контракта; их поддержка не заявляется.

Ограничения: фиксированная holdout-валидация может переобучаться при многократном
выборе; оценка скрытого теста неизвестна. Локальный лимит вызовов/токенов не
заменяет дневную денежную квоту организаторов. Контейнерные ограничения CPU,
RAM и доступа к сети задаются средой запуска; ограничения дочерних процессов
на Linux дополняют, а не заменяют их.
